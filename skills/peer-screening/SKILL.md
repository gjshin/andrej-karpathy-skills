# Peer Screening

피평가회사의 비교기업 후보를 좁히고, **근거가 남는 형태로** 정리한다.

이 스킬은 후보를 추천할 뿐 확정하지 않는다. 최종 선정은 사용자의 판단이며,
배수·WACC 계산은 여기서 하지 않는다 — 그것은 GPCM(로컬 엑셀 앱)의 몫이다.
산식이 필요한 계산을 채팅에서 하면 근거가 남지 않는다.

## 0. 시작 전 확인 — 모르면 묻는다, 추측하지 않는다

1. **피평가회사** — 비상장이면 사업 내용을 한 줄로 받는다.
2. **평가기준일** — 이것이 도구 선택을 가른다:
   - 현재 시점 검토 → `peergroup_get_population_latest` (오늘자 KRX 명단)
   - 과거 기준일 소급 → `peergroup_get_population` (분기말 스냅샷, 재현 보증)
3. **수익성 조건** — 기본은 "영업흑자"이며 이것만 배제 기준으로 쓴다.
   **매출 규모는 배제 기준이 아니다** — 피평가회사 대비 배수를 계산해 보여주되,
   규모가 다르다는 이유로 빼는 판단은 사용자 몫으로 남긴다.
   사용자가 명시적으로 규모 상하한을 주면 그때만 배제 기준으로 쓴다.

## 1. 도구 분담 — 어기지 않는다

| 용도 | 도구 | 주의 |
|---|---|---|
| 모집단 (현재 시점) | **1순위: 로컬 gpcm `list_krx_companies`** (데스크톱에 있을 때) | 이 PC에서 KRX 직접 조회 — 상폐 반영, 주요제품 포함. 재현 안 됨 → 조회일 기록 |
| 모집단 (현재 시점, 로컬 도구 없을 때) | dcfpeer `peergroup_get_population_latest` | KRX가 클라우드를 막으면 저장 명단으로 폴백한다 — 응답 meta에 `fallback`이 있으면 **명단이 빌드 시점**임을 기록에 남긴다 |
| 모집단 (소급) | dcfpeer `peergroup_get_population` | `snapshotDate`·`populationHash` 기록. 명단은 빌드 시점 기준 — 그 이후 상장폐지 미반영을 명시 |
| 종목코드 → 고유번호 | mydart `search_company` | **목록으로 한 번에.** `not_found`는 반드시 사용자에게 보고 |
| 매출·영업이익·자산·자본 | mydart `compare_financials` | 10개씩 나눠 호출 |
| 주식수 | mydart `get_periodic_report_item` "주식의 총수 현황" | corp_codes 목록으로 한 번에 |
| 사업내용 훑기 | dcfpeer 모집단의 요약 / `get_business_content` | 스냅샷 요약의 매출비중은 **3분기 누계** — 연간으로 인용하지 않는다 |
| 사업내용 원문·최신 | mydart `search_disclosures` + `get_disclosure_document` | 신규상장사 등 캐시에 없는 회사 |
| 기준일 종가 | dcfpeer `get_close_as_of` | 종가만 필요할 때 **반드시 이것** — `valuation_get_data`는 베타·재무·XBRL을 함께 돌려 타임아웃이 난다 |
| 베타 | dcfpeer `valuation_get_data` 또는 `compute_beta` | 필요할 때만. **재무 필드(ibd·nci·pretaxIncome)는 쓰지 않는다** — 재무는 전부 mydart |

## 2. 절차

### ① 모집단
- KSIC 업종코드를 알면 코드로, 모르면 키워드로 조회한다.
- 키워드 조회는 소자·장비·소재·유통이 한 목록에 섞인다. 결과를 그대로
  다음 단계에 넘기지 말고 반드시 ②를 거친다.

### ② 계층 확정
- `product`(주요제품) 열로 후보를 계층(예: 소자 / 장비 / 소재 / 패키징 / 유통)으로
  나누고, 피평가회사가 어느 계층인지 **사용자에게 확인**한다.
- 같은 계층만 남긴다. 목표: 다음 단계에 넘길 후보 50개 이하.

### ③ 코드 변환
- 남은 종목코드 전체를 `search_company`에 **목록으로 한 번에** 넣는다.
- `not_found`가 있으면 어느 회사인지 밝히고, 빠진 채 진행해도 되는지 확인한다.

### ④ 수익성 스크리닝 + 규모 표시
- `compare_financials`로 매출·영업이익을 받는다.
  **연도는 사용자가 말한 그대로.** 관행적으로 작년을 넣지 않는다.
- **배제하는 것은 영업적자뿐이다** (사용자가 규모 상하한을 명시한 경우는 예외).
- 매출은 피평가회사 대비 배수를 계산해 열로 보여준다. 배수가 크게 벗어나는
  회사(예: 10배 이상, 1/10 이하)는 ⚠️ 표시로 눈에 띄게 하되 **판정은 바꾸지
  않는다** — 규모로 뺄지는 사용자가 정한다.
- `empty`·`failed`로 돌아온 회사는 "탈락"이 아니라 "확인 불가"로 따로 표시한다.

### ⑤ 기준일 시가총액
④ 통과 후보에 대해서만 산정한다 (모집단 전체를 조회하면 호출이 낭비된다).

- **주가**: dcfpeer `get_close_as_of` — 기준일 종가와 실제 거래일을 준다.
  최대 30개씩 배치. `failed`로 돌아온 종목은 "확인 불가"로 표시한다.
  (`valuation_get_data`로 종가를 받지 않는다 — 베타·재무·XBRL이 딸려와
  대형 연결법인에서 타임아웃이 난다.)
- **유통주식수**: mydart `get_periodic_report_item` "주식의 총수 현황" —
  기준일이 속한 분기의 보고서로. 발행총수가 아니라 **유통주식수**를 쓴다.
- **시가총액 = 기준일 종가 × 유통주식수.** 주가와 주식수의 출처 시점이 다르므로
  (종가는 기준일, 주식수는 보고서 기준일) 둘 다 표에 남긴다.
- 매출과 같은 원칙: **시총으로 자동 배제하지 않는다.** 대상 대비 배수를 보여주고
  ⚠️만 붙인다. 규모로 뺄지는 사용자가 정한다.

### ⑥ 사업 유사성
- ④ 통과 후보만 사업내용을 읽고 피평가회사와의 유사성을 판단한다.
- 최종 후보 2~3개는 요약이 아니라 원문으로 확인한다.

### ⑦ 정리
- 플래그(스팩·관리종목·12월 외 결산·상장 2년 미만 = Weekly-2Y 베타 불가,
  5년 미만 = Monthly-5Y 불가)는 **자동 배제하지 않는다.** 사유와 함께 제시하고
  판단을 넘긴다.

## 3. 산출 — 엑셀 파일이 최종 산출물이다

채팅 표는 흘러가면 끝이다. 모집단과 스크리닝 과정 전체를 **엑셀 파일 하나**로
만들어 전달한다. 이 파일이 "왜 이 피어들인가"에 대한 증빙이다.

**시트 1 `스크리닝_기록`** — 조서에 그대로 옮길 수 있게:

```
피평가회사:  <회사명> (<종목코드 또는 비상장>)
평가기준일:  YYYY-MM-DD
조회일:      YYYY-MM-DD
모집단:      <도구명> / <조회 조건>
             (스냅샷이면 snapshotDate·populationHash, 실시간이면 "재현 불가 — 본 파일이 증빙")

단계별 통과:  모집단 N사 → 계층 확정 M사 → 규모·수익성 K사 → 사업내용 검토 → 추천 P사
스크리닝 조건: <규모·수익성 조건 그대로>
확인 불가:    <회사명 — 사유> (없으면 "없음")
```

**시트 2 `모집단_전체`** — 모집단 **전원**, 한 줄도 빼지 않는다. 자동필터를 건다.

| 종목코드 | 회사명 | 시장 | 주요제품 | 결산월 | 계층 | 매출 | 매출배수 | 영업이익 | 기준일종가 | 유통주식수 | 시가총액 | 시총배수 | 판정 | 배제 사유 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- 매출배수·시총배수는 피평가회사 대비. 피평가회사가 비상장이면 시총배수는 비운다.
- 시가총액 관련 열은 ④를 통과한 회사만 채워진다. 그 앞에서 배제된 회사는
  비워 두되, 배제 사유가 그 이유를 설명해야 한다.

- `판정`은 셋 중 하나: **선정 후보** / **배제** / **확인 불가**
- `배제 사유`는 구체적으로: "계층 상이(장비사)", "영업적자",
  "관리종목 — 사용자 판단으로 배제" 등. **매출 규모는 배제 사유가 아니다** —
  배수 열에 ⚠️를 붙여 보여주고 판단을 넘긴다
- 계층에서 걸러져 재무를 조회하지 않은 회사는 매출·영업이익을 비워 두되
  배제 사유에 그 사실을 적는다 — 빈칸이 "0"으로 읽히면 안 된다

**시트 3 `선정_후보`** — 추천 피어만. GPCM에 넣을 정보 중심으로:

| 종목코드 | 회사명 | 주요제품 | 매출 | 매출배수 | 영업이익 | 기준일종가(거래일) | 유통주식수 | 시가총액 | 시총배수 | 선정 근거(한 줄) |
|---|---|---|---|---|---|---|---|---|---|---|

- 기준일종가 옆에 실제 거래일(`priceDate`)을 괄호로 적는다 — 휴장·거래정지면
  기준일보다 앞선 날짜가 나오며, 그 사실이 숨으면 안 된다.
- 유통주식수는 어느 보고서에서 왔는지(예: 2025 사업보고서) 시트 하단에 주석으로 남긴다.

**채팅 답변**은 요약만 한다: 단계별 통과 수, 추천 피어와 근거 한 줄씩,
그리고 GPCM 투입용 종목코드 코드블록.

**피평가회사가 상장사면 그 종목코드를 맨 앞에 포함한다** — GPCM에서 피어와
같은 기준으로 함께 돌려야 비교가 되기 때문이다. 비상장이면 피어만 넣고,
그 사실을 한 줄 밝힌다.

```
005930   ← 피평가회사
000660
143160
```

(붙여넣기용 블록에는 주석 없이 코드만 넣는다)

## 3-b. GPCM 직접 실행 (로컬 `run_gpcm` 도구가 보일 때)

Claude 데스크톱에 gpcm 로컬 MCP가 등록돼 있으면, 종목코드를 건네는 대신
GPCM을 바로 실행할 수 있다. 단:

1. **반드시 사용자에게 슬레이트 확정을 먼저 받는다.** "이 목록으로 GPCM을
   돌릴까요?" — 확정 없이 자동 실행하지 않는다. 기준일(기간)과 WACC 파라미터를
   기본값과 다르게 할지도 이때 확인한다.
2. 확정되면 `run_gpcm(tickers, start_period, ...)` 호출. 기간은 `"2025.4Q"` 형식,
   기준일은 마지막 기간의 분기말이다.
3. 실행은 백그라운드다 — `gpcm_status`로 완료를 확인한 뒤 **파일 경로와
   Data_Quality 요약(ERROR·WARN 건수)을 함께** 전달한다. ERROR가 있으면
   해당 값은 수집 실패로 0이 들어가 있다고 명시한다.
4. 도구가 없으면(웹 등) 위의 종목코드 블록 방식으로 돌아간다.

## 4. 철칙

- 숫자를 지어내지 않는다. 조회가 실패하면 실패했다고 쓴다.
- 회사가 목록에서 소리 없이 사라지게 두지 않는다 — `not_found`·`empty`·`failed`는
  전부 표면에 드러낸다.
- 후보가 100개를 넘으면 재무 조회 전에 계층으로 먼저 좁힌다
  (mydart 상한: compare 10개/회, 정기보고서 60건/회).
- 추천으로 끝낸다. "확정은 사용자 몫"을 마지막에 명시한다.

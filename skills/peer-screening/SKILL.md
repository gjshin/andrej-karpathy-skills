# Peer Screening

피평가회사의 비교기업 후보를 좁히고, **근거가 남는 형태로** 정리한다.

이 스킬은 후보를 추천할 뿐 확정하지 않는다. 최종 선정은 사용자의 판단이며,
배수·WACC 계산은 여기서 하지 않는다 — 그것은 GPCM(로컬 엑셀 앱)의 몫이다.
산식이 필요한 계산을 채팅에서 하면 근거가 남지 않는다.

## 0. 시작 전 확인 — 모르면 묻는다, 추측하지 않는다

1. **피평가회사** — 비상장이면 사업 내용을 한 줄로 받는다.
2. **평가기준일** — 이것이 도구 선택을 가른다:
   - 현재 시점 검토 → `peergroup_get_population_latest` (오늘자 KRX 명단)
   - 과거 기준일 소급 → `peergroup_get_population` (분기말 스냅샷, 재현 보증)
3. **수익성 조건** — 기본은 "영업흑자"이며 이것만 배제 기준으로 쓴다.
   **매출 규모는 배제 기준이 아니다** — 피평가회사 대비 배수를 계산해 보여주되,
   규모가 다르다는 이유로 빼는 판단은 사용자 몫으로 남긴다.
   사용자가 명시적으로 규모 상하한을 주면 그때만 배제 기준으로 쓴다.

## 1. 도구 분담 — 어기지 않는다

| 용도 | 도구 | 주의 |
|---|---|---|
| 모집단 (현재 시점) | **1순위: 로컬 gpcm `list_krx_companies`** (데스크톱에 있을 때) | 이 PC에서 KRX 직접 조회 — 상폐 반영, 주요제품 포함. 재현 안 됨 → 조회일 기록 |
| 모집단 (현재 시점, 로컬 도구 없을 때) | dcfpeer `peergroup_get_population_latest` | KRX가 클라우드를 막으면 저장 명단으로 폴백한다 — 응답 meta에 `fallback`이 있으면 **명단이 빌드 시점**임을 기록에 남긴다 |
| 모집단 (소급) | dcfpeer `peergroup_get_population` | `snapshotDate`·`populationHash` 기록. 명단은 빌드 시점 기준 — 그 이후 상장폐지 미반영을 명시 |
| 종목코드 → 고유번호 | mydart `search_company` | **목록으로 한 번에.** `not_found`는 반드시 사용자에게 보고 |
| 매출·영업이익·자산·자본 | mydart `compare_financials` | 10개씩 나눠 호출 |
| 주식수 | mydart `get_periodic_report_item` "주식의 총수 현황" | corp_codes 목록으로 한 번에 |
| 사업내용 훑기 | dcfpeer 모집단의 요약 / `get_business_content` | 스냅샷 요약의 매출비중은 **3분기 누계** — 연간으로 인용하지 않는다 |
| 사업내용 원문·최신 | mydart `search_disclosures` + `get_disclosure_document` | 신규상장사 등 캐시에 없는 회사 |
| 감사의견 이력 | mydart `get_periodic_report_item` "회계감사인의 명칭 및 감사의견" | **④ 통과 후보 전원 필수.** 회사·연도를 목록으로 한 번에. 조회 상한 60회 = 회사수 × 연도수 |
| 거래 적격성 이력 | mydart `search_disclosures` `pblntf_ty="I"` | **④ 통과 후보 전원 필수.** 기간은 평가기준일 기준 최소 5년 소급 |
| 기준일 종가 | dcfpeer `get_close_as_of` | 종가만 필요할 때 **반드시 이것** — `valuation_get_data`는 베타·재무·XBRL을 함께 돌려 타임아웃이 난다. **기준일 종가가 나왔다는 것은 그 날 거래됐다는 뜻일 뿐, 과거에 정지된 적 없다는 증거가 아니다** |
| 베타 | dcfpeer `valuation_get_data` 또는 `compute_beta` | 필요할 때만. **재무 필드(ibd·nci·pretaxIncome)는 쓰지 않는다** — 재무는 전부 mydart |

## 2. 절차

### ① 모집단
- KSIC 업종코드를 알면 코드로, 모르면 키워드로 조회한다.
- 키워드 조회는 소자·장비·소재·유통이 한 목록에 섞인다. 결과를 그대로
  다음 단계에 넘기지 말고 반드시 ②를 거친다.

### ② 계층 확정
- `product`(주요제품) 열로 후보를 계층(예: 소자 / 장비 / 소재 / 패키징 / 유통)으로
  나누고, 피평가회사가 어느 계층인지 **사용자에게 확인**한다.
- 같은 계층만 남긴다. 목표: 다음 단계에 넘길 후보 50개 이하.

### ③ 코드 변환
- 남은 종목코드 전체를 `search_company`에 **목록으로 한 번에** 넣는다.
- `not_found`가 있으면 어느 회사인지 밝히고, 빠진 채 진행해도 되는지 확인한다.

### ④ 수익성 스크리닝 + 규모 표시
- `compare_financials`로 매출·영업이익을 받는다.
  **연도는 사용자가 말한 그대로.** 관행적으로 작년을 넣지 않는다.
- **배제하는 것은 영업적자뿐이다** (사용자가 규모 상하한을 명시한 경우는 예외).
- 매출은 피평가회사 대비 배수를 계산해 열로 보여준다. 배수가 크게 벗어나는
  회사(예: 10배 이상, 1/10 이하)는 ⚠️ 표시로 눈에 띄게 하되 **판정은 바꾸지
  않는다** — 규모로 뺄지는 사용자가 정한다.
- `empty`·`failed`로 돌아온 회사는 "탈락"이 아니라 "확인 불가"로 따로 표시한다.

### ④-b 거래 적격성 검증 — 건너뛰지 않는다

④를 통과한 후보 **전원**을 세 갈래로 본다. 셋 다 평가기준일 기준 **최소 5년
소급** — 베타 회귀구간과 같은 기간을 봐야 한다. 하나라도 건너뛰면 그 회사는
"클린"이 아니라 **"미조회"**다.

#### ④-b-1 감사의견 이력 (자동, 한 번에)

`get_periodic_report_item(item="회계감사인의 명칭 및 감사의견")`에 **후보 전원의
corp_codes 와 최근 5개 사업연도를 목록으로 넣어 한 번에** 부른다. 회사마다,
연도마다 따로 부르지 않는다.

- **조회 상한은 60회 = 회사수 × 연도수다.** 12사 × 5년 = 60이 한 번에 되는 최대치다.
  넘으면 **회사를 나눠** 두 번 부른다 — 연도를 줄이지 않는다. 5년은 베타 구간에
  맞춘 것이라 3년으로 줄이면 검증 자체가 헐거워진다.
- 응답에 실린 필드(감사의견·강조사항 등)를 **그대로** 표로 옮긴다. 요약해서
  "문제 없음"으로 바꾸지 않는다.

| 발견 | 처리 |
|---|---|
| 적정 외 의견 (한정·부적정·의견거절) | **배제 권고.** 해당 사업연도를 명시 |
| 계속기업 관련 중요한 불확실성 (강조사항) | **배제 권고 후보로 표면화.** 연도를 적고 판단을 넘긴다 |
| 감사인 교체가 잦음 (지정감사 포함) | 사유가 아니라 사실만 적고 판단을 넘긴다 |
| `empty`·`failed` | "미조회"로 표시한다. **없음으로 읽지 않는다** |

#### ④-b-2 거래소공시 (정지·심사 이력)

`search_disclosures`를 `pblntf_ty="I"`(거래소공시)로 같은 기간 훑는다.

**모집단 스냅샷의 `flags`로 갈음하지 않는다.** `isAdministrative`는 관리종목만 잡고
상장적격성 실질심사·매매거래정지는 커버하지 않는다. 스냅샷일에 거래정지 중이던
종목도 `false`로 나온다.

**기준일 종가가 정상 반환된 것도 근거가 아니다.** 그 날 거래됐다는 사실은
3년 전 정지 이력과 무관하다. 한 점을 보고 구간을 판단하지 않는다.

찾는 것 — 보고서명에 아래가 있으면 전부 표면에 올린다:

| 발견 | 처리 |
|---|---|
| 상장적격성 실질심사 사유 발생 / 개선기간 부여 / 기업심사위원회 | **배제 권고.** 정지 기간과 해제일을 명시 |
| 매매거래정지 (무상증자·액면분할 등 통상 사유 제외) | 기간을 세어 베타 구간과 겹치는지 본다 |
| 상장폐지 기준 해당 / 이의신청 / 투자유의안내 | **배제 권고** |
| 감사·검토의견 부적정·의견거절, 완전자본잠식 | **배제 권고** |
| 불성실공시법인 지정 | 시점·경중을 적고 판단을 넘긴다 |
| 횡령·배임 혐의 발생, 경영권 분쟁 소송 | 사유를 적고 판단을 넘긴다 |

배제를 권고하는 이유는 도덕적 평가가 아니라 **숫자가 안 나오기 때문**이다:

- **베타 산정 불가** — 정지 구간은 주가가 결측이라 5Y 월간·2Y 주간 회귀가 무의미하다.
  WACC에 그대로 흘러든다.
- **가격발견 미완결** — 거래재개 직후의 시가총액은 배수의 분자로 못 쓴다.
  재개 후 몇 개월인지 세고, 재개 이후 "현저한 시황변동" 조회공시가 있었는지 본다.
- **계속기업 표본 부적합** — 손상·감액이 실적에 섞여 EV/EBIT이 왜곡된다.

무상증자 권리락 1일 정지처럼 통상적인 건 결격이 아니다 — 다만 "통상 사유"라고
적어 검증했음을 남긴다. 검증하지 않은 회사는 "클린"이 아니라 **"미조회"**로 적는다.

#### ④-b-3 정량 교차확인

로컬 gpcm의 `check_trading_gaps`가 있으면 같은 후보에 실행한다.
공시는 사유를, 이것은 시세 결측 구간의 실측(연속 5거래일 이상)을 준다. 공시 제목에
안 잡힌 결측이 나오면 원인을 공시로 되짚고, 반대로 공시상 정지가 시세 결측과
맞는지 기간을 대조한다. 결과 구간·일수는 검증 열에 병기한다.

### ⑤ 기준일 시가총액
④·④-b 통과 후보에 대해서만 산정한다 (모집단 전체를 조회하면 호출이 낭비된다).

- **주가**: dcfpeer `get_close_as_of` — 기준일 종가와 실제 거래일을 준다.
  최대 30개씩 배치. `failed`로 돌아온 종목은 "확인 불가"로 표시한다.
  (`valuation_get_data`로 종가를 받지 않는다 — 베타·재무·XBRL이 딸려와
  대형 연결법인에서 타임아웃이 난다.)
- **유통주식수**: mydart `get_periodic_report_item` "주식의 총수 현황" —
  기준일이 속한 분기의 보고서로. 발행총수가 아니라 **유통주식수**를 쓴다.
- **시가총액 = 기준일 종가 × 유통주식수.** 주가와 주식수의 출처 시점이 다르므로
  (종가는 기준일, 주식수는 보고서 기준일) 둘 다 표에 남긴다.
- 매출과 같은 원칙: **시총으로 자동 배제하지 않는다.** 대상 대비 배수를 보여주고
  ⚠️만 붙인다. 규모로 뺄지는 사용자가 정한다.

### ⑥ 사업 유사성
- ④ 통과 후보만 사업내용을 읽고 피평가회사와의 유사성을 판단한다.
- 최종 후보 2~3개는 요약이 아니라 원문으로 확인한다.

### ⑦ 정리
- 플래그(스팩·관리종목·12월 외 결산·상장 2년 미만 = Weekly-2Y 베타 불가,
  5년 미만 = Monthly-5Y 불가·거래정지 이력)는 **자동 배제하지 않는다.**
  사유와 함께 제시하고 판단을 넘긴다.

## 3. 산출 — 엑셀 파일이 최종 산출물이다

채팅 표는 흘러가면 끝이다. 모집단과 스크리닝 과정 전체를 **엑셀 파일 하나**로
만들어 전달한다. 이 파일이 "왜 이 피어들인가"에 대한 증빙이다.

**시트 1 `스크리닝_기록`** — 조서에 그대로 옮길 수 있게:

```
피평가회사:  <회사명> (<종목코드 또는 비상장>)
평가기준일:  YYYY-MM-DD
조회일:      YYYY-MM-DD
모집단:      <도구명> / <조회 조건>
             (스냅샷이면 snapshotDate·populationHash, 실시간이면 "재현 불가 — 본 파일이 증빙")

단계별 통과:  모집단 N사 → 계층 확정 M사 → 규모·수익성 K사 → 거래 적격성 J사 → 사업내용 검토 → 추천 P사
스크리닝 조건: <규모·수익성 조건 그대로>
거래 적격성:  <조회 도구·기간 — 감사의견/거래소공시/시세결측 셋 다> /
             부적격 <회사명 — 사유(의견·정지기간)>
확인 불가:    <회사명 — 사유> (없으면 "없음")
```

**시트 2 `모집단_전체`** — 모집단 **전원**, 한 줄도 빼지 않는다. 자동필터를 건다.

| 종목코드 | 회사명 | 시장 | 주요제품 | 결산월 | 계층 | 매출 | 매출배수 | 영업이익 | 기준일종가 | 유통주식수 | 시가총액 | 시총배수 | 감사의견 | 거래정지·실질심사 검증 | 판정 | 배제 사유 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|

- `감사의견` 열은 조회한 5년 중 **적정이 아닌 해**와 **계속기업 불확실성이 있는 해**를
  적는다(예: "2023 한정", "2024 계속기업 강조"). 전부 적정이면 "적정(5년)",
  조회하지 않았으면 **"미조회"** — 빈칸으로 두지 않는다.

- `거래정지·실질심사 검증` 열은 셋 중 하나로만 적는다: **클린**(사유와 함께) /
  **부적격**(정지기간·해제일 명시) / **미조회**(계층에서 걸러져 확인하지 않음).
  빈칸으로 두지 않는다 — 빈칸이 "클린"으로 읽히면 안 된다.

- 매출배수·시총배수는 피평가회사 대비. 피평가회사가 비상장이면 시총배수는 비운다.
- 시가총액 관련 열은 ④를 통과한 회사만 채워진다. 그 앞에서 배제된 회사는
  비워 두되, 배제 사유가 그 이유를 설명해야 한다.

- `판정`은 셋 중 하나: **선정 후보** / **배제** / **확인 불가**
- `배제 사유`는 구체적으로: "계층 상이(장비사)", "영업적자",
  "관리종목 — 사용자 판단으로 배제" 등. **매출 규모는 배제 사유가 아니다** —
  배수 열에 ⚠️를 붙여 보여주고 판단을 넘긴다
- 계층에서 걸러져 재무를 조회하지 않은 회사는 매출·영업이익을 비워 두되
  배제 사유에 그 사실을 적는다 — 빈칸이 "0"으로 읽히면 안 된다

**시트 3 `선정_후보`** — 추천 피어만. GPCM에 넣을 정보 중심으로:

| 종목코드 | 회사명 | 주요제품 | 매출 | 매출배수 | 영업이익 | 기준일종가(거래일) | 유통주식수 | 시가총액 | 시총배수 | 적격성 검증 | 선정 근거(한 줄) |
|---|---|---|---|---|---|---|---|---|---|---|---|

- 적격성 검증: ④-b 결과 세 갈래를 한 칸에 — 감사의견 / 정지·심사 이력 / 시세 결측 구간. 클린이면 "클린(감사의견 적정 5년, 통상 사유 정지만)"처럼 근거와 함께.
- 기준일종가 옆에 실제 거래일(`priceDate`)을 괄호로 적는다 — 휴장·거래정지면
  기준일보다 앞선 날짜가 나오며, 그 사실이 숨으면 안 된다.
- 유통주식수는 어느 보고서에서 왔는지(예: 2025 사업보고서) 시트 하단에 주석으로 남긴다.

**채팅 답변**은 요약만 한다: 단계별 통과 수, 추천 피어와 근거 한 줄씩,
그리고 GPCM 투입용 종목코드 코드블록.

**피평가회사가 상장사면 그 종목코드를 맨 앞에 포함한다** — GPCM에서 피어와
같은 기준으로 함께 돌려야 비교가 되기 때문이다. 비상장이면 피어만 넣고,
그 사실을 한 줄 밝힌다.

```
005930   ← 피평가회사
000660
143160
```

(붙여넣기용 블록에는 주석 없이 코드만 넣는다)

## 3-b. GPCM 직접 실행 (로컬 `run_gpcm` 도구가 보일 때)

Claude 데스크톱에 gpcm 로컬 MCP가 등록돼 있으면, 종목코드를 건네는 대신
GPCM을 바로 실행할 수 있다. 단:

1. **반드시 사용자에게 슬레이트 확정을 먼저 받는다.** "이 목록으로 GPCM을
   돌릴까요?" — 확정 없이 자동 실행하지 않는다. 기준일(기간)도 이때 확인한다.
1-b. **먼저 `get_wacc_inputs(as_of=<평가기준일>)`로 기준일 시장금리를 조회한다.**
   `as_of` 에는 run_gpcm 과 **같은 기준일**을 넣는다 — 기간 표기(`"2025.4Q"`)를
   그대로 넣어도 분기말로 읽는다. 오늘 금리를 넣으면 조서의 다른 숫자와 시점이 어긋난다.
   rf·kd는 판단이 아니라 그날의 관측치다. 조회된 값·금리기준일·출처를 보여주며
   묻고, **확정 없이 그대로 쓰지 않는다.** 조회가 실패하면 실패했다고 말하고
   사용자에게 직접 받는다 — 기본값으로 조용히 메우지 않는다.
   등급은 평가대상 신용도에 맞추고(`bond_grade="AA-"` 또는 `"BBB-"`), **만기는
   평가 대상 현금흐름의 기간에 맞춘다** — 기본은 국고채 5년이나, 영구현금흐름을
   전제하면 `rf_maturity="10년"`처럼 바꿔 부른다. 만기 선택도 판단이므로
   무엇을 썼는지 근거에 남긴다.
1-c. **WACC 파라미터 6개를 하나씩 개별 질문해 확정받는다** (사용자가 이미
   말했거나 "전부 기본값"이라 답한 항목은 생략):
   ① rf 무위험이자율 (조회값 제시, 기본 3.3%)
   ② mrp — 한국공인회계사회 시장위험 프리미엄 가이던스(2026.06.05) **7~9%** 범위,
     기본 8.0%. 가이던스는 한공회 입장이며 그대로 쓸 의무는 없다
   ③ 사이즈 프리미엄 — 한국공인회계사회 기업규모위험 프리미엄 연구결과(2026.06.05)
     3분위 기준으로 시총 구간을 안내한다:
     **2,583억 이하 4.02% / 2,585~8,671억 1.19% / 8,679억 초과 -0.45% / 미적용 0**
     (5분위: 1,759억 이하 4.86% / ~3,135억 2.67% / ~6,600억 0.97% /
     ~18,794억 -0.06% / 초과 -0.51%)
     ⑤에서 구한 피평가회사 시가총액으로 구간을 짚어 제시하되 **확정은 사용자**가 한다
   ④ kd 세전 (기본 3.5%)
   ⑤ 법인세율 — **묻지 않는다.** 비워 두면 피평가회사의 세전이익과 사업연도
     세율표로 자동 산출된다(한국 법인 전제). 결과 보고 때 산출 근거
     (세전이익·사업연도·적용세율)를 함께 전한다.
   ⑥ 베타 종류 (5Y 월간 / 2Y 주간)
   ⑧ 일별 주가 시트 `daily_prices` — **묻지 않는다.** 기본 `"5Y"` (Price_Daily 시트에
     기준일까지 5년치 일별 종가). 베타에 쓴 시계열을 자르는 것이라 조회가 늘지 않는다.
     사용자가 필요 없다고 하면 `"off"`.
   ⑦ 베타 기준지수 — **묻지 않는다.** 기본은 코스피 일괄(`beta_benchmark="KOSPI"`).
     피어 무차입베타를 평균해 하나의 WACC 을 만들므로 모든 β 가 같은 지수 기준이어야
     하고, MRP 도 시장 전체 기준 추정치이기 때문이다. **피어와 피평가회사가 전부
     코스닥이고 MRP 도 그에 맞춰 정한 경우에만** 사용자가 요청할 때
     `beta_benchmark="MARKET"` 을 쓴다 (코스닥 종목은 ^KQ11 기준).
   기본값을 임의로 적용해 호출하지 않는다.
2. 확정되면 `run_gpcm(tickers, start_period, ...)` 호출. 기간은 `"2025.4Q"` 형식,
   기준일은 마지막 기간의 분기말이다. **`rate_source`에 `get_wacc_inputs`의
   `citation`을 그대로 넘긴다** — 엑셀 Notes에 "이 rf는 어디서 왔나"의 답이 남는다.
   손으로 정한 값이면 그 근거를 문장으로 적어 넘긴다.
3. 실행은 백그라운드다 — `gpcm_status`로 완료를 확인한 뒤 **파일 경로와
   Data_Quality 요약(ERROR·WARN 건수)을 함께** 전달한다. ERROR가 있으면
   해당 값은 수집 실패로 0이 들어가 있다고 명시한다.
4. 도구가 없으면(웹 등) 위의 종목코드 블록 방식으로 돌아간다.

## 4. 철칙

- 숫자를 지어내지 않는다. 조회가 실패하면 실패했다고 쓴다.
- **한 시점의 데이터로 구간을 판단하지 않는다.** 기준일 종가가 나왔다는 것은
  그 날 거래됐다는 뜻일 뿐이다. 베타는 구간을 쓰므로 구간을 확인해야 한다.
- **플래그가 없다는 것은 확인했다는 뜻이 아니다.** 스냅샷 플래그가 커버하는 범위를
  알고 쓰고, 커버하지 않는 것은 직접 조회한다.
- **조회한 값을 확정 없이 쓰지 않는다.** 시장금리처럼 자동으로 받아온 값도 후보일
  뿐이다. 값과 출처를 보여주고 사용자가 정한다. 근거는 산출물에 남긴다.
- 회사가 목록에서 소리 없이 사라지게 두지 않는다 — `not_found`·`empty`·`failed`는
  전부 표면에 드러낸다.
- 후보가 100개를 넘으면 재무 조회 전에 계층으로 먼저 좁힌다
  (mydart 상한: compare 10개/회, 정기보고서 60건/회).
- 추천으로 끝낸다. "확정은 사용자 몫"을 마지막에 명시한다.
